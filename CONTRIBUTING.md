# Работа с кодом ParamForge

Карта исходников и основания архитектурных решений находятся в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Размещение изменений

Добавляйте код к той обязанности, которая изменяется: расчёт — в ядро, реакцию на действия — в интерфейс, оформление Word — в Documents. Новый самостоятельный тип получает файл с тем же именем. Небольшие вложенные вспомогательные типы могут оставаться рядом с владельцем.

Новые наборы проверок называйте по функции. Название версии относится к журналу выпуска, а не к структуре исходников. Расчёты не должны зависеть от WinForms. Общий план обработки не должен содержать команды конкретного ЧПУ.

Существующие имена сериализованных свойств, точность координат, правила округления и поведение экспорта меняются только как отдельное функциональное изменение с проверками совместимости.

## Оформление

Правила редактора заданы в `.editorconfig`: четыре пробела для C#, скобки Allman, отдельные действия на отдельных строках. Имена типов и методов — `PascalCase`, интерфейсов — с `I`; существующий `camelCase` закрытых полей сохраняется. Длинные вызовы разбиваются по аргументам; блоки не сжимаются в одну строку. Короткие свойства и простые выражения могут оставаться однострочными.

Комментарии объясняют причину решения, единицы измерения, точность или технологическое ограничение. Не пересказывайте строку кода комментарием. Для нестандартного алгоритма укажите исходное правило или источник.

Базовые рекомендации: [Microsoft C# conventions](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/coding-style/coding-conventions) и [dotnet/runtime project guidelines](https://github.com/dotnet/runtime/blob/main/docs/coding-guidelines/project-guidelines.md). Это принятые соглашения проекта, а не заявление о формальной сертификации.

## Команды

SDK закреплён в `global.json`. Из корня репозитория:

```powershell
# Сборка, проверка стиля и 423 проверки ядра:
.\scripts\check.ps1

# То же с проверками настоящих окон WinForms:
.\scripts\check.ps1 -Ui

# Исправить расположение пробелов и переносов:
dotnet format whitespace Kontur.sln --no-restore

# Добавить скобки и удалить неиспользуемые using:
dotnet format style Kontur.sln --no-restore --diagnostics IDE0011 IDE0005 IDE0040 --severity info

# Подготовить локальную сборку приложения:
.\scripts\build.ps1
```

UI-проверки открывают окна; запускайте их после завершения редактирования. `check.ps1 -Ui` автоматически выбирает новый каталог отчёта. При ручном запуске также используйте новый или пустой каталог:

```powershell
dotnet run --project src/Kontur.Desktop.Tests -c Release -- --smoke-output qa/ui-new-run
```

В обычной программе тестового обработчика командной строки больше нет. Старые отчёты описывают команды соответствующих старых сборок.

Проверки Word в ядре проверяют ZIP/XML и содержимое. Если меняется вёрстка карт, требуется отдельный визуальный просмотр страниц. Изменения постпроцессора требуют сравнения восстановленных движений обоих диалектов; статическая проверка не заменяет прогон на ЧПУ.
