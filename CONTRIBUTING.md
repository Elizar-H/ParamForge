# Разработка ParamForge

Нужны Visual Studio 2022 (17.5 или новее) либо 2026 с компонентами «Разработка классических приложений на C++» и CMake, а также Qt 6.12 для MSVC x64. Стандартный путь Qt — `C:\Qt\6.12.0\msvc2022_64`; другой путь можно указать переменной окружения `PARAMFORGE_QT_ROOT`. MinGW-комплект Qt для этой сборки не подходит. При первой сборке CMake скачивает закреплённые версии nlohmann/json и miniz.

## Открытие в Visual Studio

1. Выберите **Файл → Открыть → Папка** и укажите папку ParamForge с `CMakeLists.txt`.
2. Дождитесь настройки CMake. Для разработки выберите **Windows x64 Debug**.
3. В списке запуска выберите **ParamForge.exe**, затем нажмите **F5**. Точки останова работают в исходных `.cpp`.

Файл `.sln` не требуется: Visual Studio читает состав проекта непосредственно из CMake. Если редактор предлагает собственные конфигурации вместо трёх из `CMakePresets.json`, включите использование CMake Presets в настройках CMake и заново откройте папку.

## Где что находится

| Папка | Содержание |
|---|---|
| `src/core` | Параметры, допуски, расчёты, маршрут и генерация/проверка УП |
| `src/files` | JSON проектов, технологические карты и выпуск документов |
| `src/desktop` | Окно, ввод, навигация, темы и изображения |
| `src/resources` | Схема параметров, значок и встроенные ресурсы |
| `tests` | Проверки поведения, которые защищают код при следующих изменениях |
| `docs`, `scripts`, `licenses` | Документация, сборка и лицензии |
| `build` | Создаваемые сборки, скачанные зависимости, журналы, проверки и архивы |
| `app` | Готовая Release-программа с библиотеками для запуска и копирования |

Начните чтение с `src/desktop/main.cpp` и `docs/ARCHITECTURE.md`. Приложение вызывает расчёты ядра, а файловый модуль сохраняет их результат. Новые файлы исходников добавляются в `CMakeLists.txt`.

## Сборка и проверки

Из PowerShell в папке проекта:

```powershell
.\scripts\build.ps1                        # Release и готовая папка app
.\scripts\build.ps1 -Configuration Debug   # Отладочная сборка
.\scripts\check.ps1 -Ui                    # Проверки ядра и интерфейса
```

Общие конфигурации — `windows-debug`, `windows-release`, `windows-checks`; результаты находятся соответственно в `build/debug`, `build/release`, `build/checks`. Тесты собираются только в Checks. После инициализации среды MSVC эти же конфигурации доступны через `cmake --preset <имя>`, `cmake --build --preset <имя>` и `ctest --preset windows-checks`.

`Запустить.cmd` открывает `app/ParamForge.exe`, при отсутствии сначала собирает Release. Для запуска готовой папки `app` средства разработки не нужны. Папки `build` и `app` не входят в Git и восстанавливаются из исходников; перед удалением остановите работающую из них программу. `.vs` — локальный кэш Visual Studio, `CMakeUserPresets.json` — необязательные личные настройки. Они также не входят в Git.

`PARAMFORGE_WORK_ROOT` меняет место журналов, проверок и упаковки, но не пути сборок и приложения. Полный дополнительный эталон можно явно указать через `PARAMFORGE_REFERENCE_FILE`; обычные проверки используют данные из `tests` и внешнего эталона не требуют.

Форматирование C++ закреплено в `.clang-format`. После изменения интерфейса нужны проверки `-Ui`; после изменения Word — просмотр отрисованных страниц. Сохранённые имена JSON и точность размеров сохраняются. Статическая проверка УП не заменяет прогон в SinuTrain или на оборудовании. Git и публикация выполняются отдельно по запросу.
