# Подготовка выпуска

Для Windows x64 публикуется автономная сборка: преподавателю не нужно устанавливать .NET. Исходники собираются из того же коммита, из которого выпущена программа.

## Сборка архивов

1. Обновить версию в `Directory.Build.props` и `Engine.Version`, путь в `Запустить.cmd` и описание выпуска.
2. Выполнить `scripts/check.ps1 -Ui`, просмотреть затронутый интерфейс. При изменении карт отдельно проверить страницы Word.
3. Проверить состав изменений и сохранить их в коммит.
4. Выполнить:

```powershell
.\scripts\package-release.ps1
```

Нужен .NET SDK из `global.json`. При публикации автономной сборки пакеты среды выполнения загружаются с nuget.org; обычная сборка проекта сохраняет свою конфигурацию источников. Скрипт по умолчанию повторяет проверки стиля и ядра. `-SkipChecks` допустим, если проверки этой версии уже выполнены.

В `release/packages` появятся:

- `ParamForge-<версия>-win-x64.zip` — приложение, краткая инструкция и JSON-примеры.
- `ParamForge-<версия>-source.zip` — исходники из коммита без `.git`, `bin`, `obj`, личных файлов и результатов локальных проверок.
- `SHA256SUMS.txt` — контрольные суммы обоих архивов.

Распаковать первый архив в отдельную папку, открыть приложение и проверить версию. Проверить перечень файлов второго архива. Не переименовывать старую программу в новый выпуск.

## GitHub Releases

Тег `v<версия>` должен указывать на проверенный коммит. В описание выпуска включить изменения, краткую инструкцию запуска и фактические ограничения испытаний. Приложить оба архива и контрольные суммы. Сначала можно подготовить черновик: неопубликованный черновик доступен владельцу репозитория, но не преподавателю по обычной публичной ссылке.

Публикация выпуска выполняется отдельно после проверки вложений. Основную ветку и историю не требуется переписывать; черновик можно подготовить из отдельной ветки выпуска.
